# Déroulement — Séance 08 LN-IA

Challenge 100 jours · Automne 2026 · Module 02 · Semaine 04
Lundi 19 octobre 2026 · 19h00 GMT
Pilotage : Prof. Abderrahman EL HISSE

## Objectif

Transformer une production V1 en livrable V2 clair, utile et présentable,
avec des contrôles, des corrections justifiées et des preuves conservées.

Fil directeur :
Préparer → Contrôler → Corriger → Prouver → Présenter → Décider humainement.

## Préparation

1. Démarrer le site local depuis le README.
2. Garder ouverts le navigateur, VS Code et le terminal Vite.
3. Préparer un dossier candidat distinct du code du site.
4. Reprendre le prompt personnel de séance 07 et une production V1 anonymisée.
5. Prévoir l’aperçu autonome comme solution de secours.

## Conducteur proposé — 90 minutes

| Temps     | Axe                     | Slides et rubriques                    | Résultat attendu                                         |
| --------- | ----------------------- | -------------------------------------- | -------------------------------------------------------- |
| 0–10 min  | Comprendre l’objectif   | Slides 1–4 ; Accueil et Présentation   | Un besoin, un public et un livrable choisis              |

| 20–30 min | Observer une correction | Slides 8–10 ; Démonstrations           | Repérer deux écarts dans un cas fictif                   |
| 30–40 min | Préparer son dossier    | Slide 11 ; Atelier et VS Code          | Conserver le prompt et la V1 sans les écraser            |

Durées indicatives. Organiser les présentations en binômes si nécessaire.

La slide 17 sur VS Code, Codex et GitHub Pages est un complément technique, à traiter après le parcours principal si le temps le permet.
Aucun commit, push ou déploiement sans autorisation explicite.

Flashcards et quiz : révision facultative après la pratique.

## Repères pour le formateur

- Les huit étapes LN-IA décrivent le cadre général.
- Les six étapes de Méthode décrivent sa mise en pratique.
- Les quatre axes de l’accueil en donnent la synthèse.
- Les slides 8–10 présentent association, formation, entreprise :
  sélectionner les démonstrations par leur nom.
- Le cas enseignement est un complément facultatif.
- Toutes les démonstrations sont fictives.

## Alternance présentation / pratique

1. Navigateur : projeter les diapositives.
2. Quitter le plein écran avec Échap et ouvrir Atelier V1 → V2.
3. Passer à VS Code avec Alt + Tab pour conserver les versions et les preuves.
4. Revenir au même onglet du navigateur pour poursuivre.

Le site n’appelle aucun service IA. Les prompts sont exécutés,
si nécessaire, dans l’outil externe choisi par le participant.

Exporter avant tout rechargement ou modification du code :
Vite peut recharger la page et les saisies ne sont pas sauvegardées.

## Preuves à conserver

Dans 02-prompts/ :
- prompt personnel ;
- réponse initiale V1 ;
- grille de contrôle ;
- journal des corrections humaines ;
- réponse corrigée V2.

Dans 07-portfolio/preuves-module-02.md :
- besoin et public ;
- sources et contrôles effectués ;
- corrections et limites ;
- feedback et décision humaine datée.

Le site propose un dossier de preuve, une V2 et une checklist à télécharger.
Vérifier leur contenu et compléter les pièces manquantes dans VS Code.

## Trame de présentation orale

1. Quel besoin et quel public ?
2. Que proposait la V1 ?
3. Quels contrôles et quelles sources ?
4. Quelles corrections humaines dans la V2 ?
5. Quelles limites et quelles questions de feedback ?

## Décision finale

VALIDÉ : preuves suffisantes et accord humain explicite.
À COMPLÉTER : pièce ou correction manquante.
À REVOIR : erreur importante ou inadéquation au besoin.

Les statuts calculés du site indiquent uniquement la complétude.
La validation réelle appartient au candidat et au formateur.
